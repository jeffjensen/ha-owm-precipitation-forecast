== Overview

This document describes the testing strategy, test structure, and how to run tests for the OWM Precipitation Forecast integration.

== Test Strategy

The integration uses a comprehensive three-tier testing approach:

1. *Unit Tests* - Test individual components in isolation
2. *Integration Tests* - Test component interactions
3. *Advanced Scenario Tests* - Test complex real-world scenarios

=== Test Coverage Goals

* *Minimum Coverage*: 90%
* *Target Coverage*: 95%+
* *Critical Paths*: 100%

----

Shows coverage with missing lines listed.

==== XML Report

[source,bash]
----
pytest --cov --cov-report=xml
----

Generates `coverage.xml` for CI/CD integration.

=== Coverage Configuration

Configuration in `pyproject.toml`:

[source,toml]
----
[tool.coverage.run]
source = ["custom_components/owm_precipitation_forecast"]
branch = true
omit = ["tests/*"]

[tool.coverage.report]
exclude_lines = [
    "pragma: no cover",
    "def __repr__",
    "if TYPE_CHECKING:",
    "raise AssertionError",
    "raise NotImplementedError",
]
----

=== Improving Coverage

1. Run coverage report
2. Identify uncovered lines
3. Add tests for uncovered code
4. Re-run coverage to verify

Example:

[source,bash]
----

pytest --cov --cov-report=term-missing

# Identify gaps
# Add tests
# Verify
pytest --cov --cov-report=html
----

== Writing Tests

=== Unit Tests

Test individual components in isolation.

==== Example: Testing a Sensor

[source,python]
----
import pytest
from homeassistant.core import HomeAssistant
from custom_components.owm_precipitation_forecast.sensor import (
    HourlyRainSensor,
)

@pytest.mark.unit
async def test_hourly_rain_sensor(hass: HomeAssistant) -> None:
    """Test hourly rain sensor."""
    coordinator = MockCoordinator()
    sensor = HourlyRainSensor(coordinator, "Test Location")
    
    assert sensor.name == "owm_precipitation_forecast_test_location_hourly_rain"
    assert sensor.unit_of_measurement == "in"
    assert sensor.native_value == 0.5
----

==== Best Practices

* Test one thing per test
* Use descriptive test names
* Mock external dependencies
* Test both success and failure cases
* Test edge cases

=== Integration Tests

Test component interactions.

==== Example: Testing Config Flow

[source,python]
----
import pytest
from homeassistant.core import HomeAssistant
from homeassistant.data_entry_flow import FlowResultType

@pytest.mark.integration
async def test_config_flow_success(hass: HomeAssistant) -> None:
    """Test successful config flow."""
    result = await hass.config_entries.flow.async_init(
        "owm_precipitation_forecast",
        context={"source": "user"}
    )
    
    assert result["type"] == FlowResultType.FORM
    assert result["step_id"] == "user"
    
    result = await hass.config_entries.flow.async_configure(
        result["flow_id"],
        user_input={
            "api_key": "test_key",
            "location_name": "Test City",
            "latitude": 45.0,
            "longitude": -93.0,
        }
    )
    
    assert result["type"] == FlowResultType.CREATE_ENTRY
    assert result["title"] == "Test City"
----

==== Best Practices

* Test complete workflows
* Verify state changes
* Check side effects
* Test error handling
* Verify data flow

=== Advanced Scenario Tests

Test complex real-world scenarios.

==== Example: Testing API Failures with Retry

[source,python]
----
import pytest
from aiohttp import ClientError
from custom_components.owm_precipitation_forecast.api_client import (
    OWMApiClient,
)

@pytest.mark.advanced
async def test_api_retry_with_exponential_backoff(
    hass: HomeAssistant,
    mock_aiohttp_session,
) -> None:
    """Test API retry with exponential backoff."""
    client = OWMApiClient("test_key", hass)
    
    # Simulate 3 failures then success
    responses = [
        ClientError("Network error"),
        ClientError("Network error"),
        ClientError("Network error"),
        {"data": "success"},
    ]
    
    mock_aiohttp_session.set_responses(responses)
    
    start_time = time.time()
    result = await client.get_forecast(45.0, -93.0)
    end_time = time.time()
    
    # Verify exponential backoff timing
    # 1s + 2s + 4s = 7s minimum
    assert end_time - start_time >= 7.0
    assert result == {"data": "success"}
    assert mock_aiohttp_session.call_count == 4
----

==== Best Practices

* Test failure scenarios
* Verify error recovery
* Test rate limiting
* Test concurrent operations
* Test data consistency

== Common Issues

=== Tests Hanging

*Problem:* Tests never complete

*Solution:*
* Check for infinite loops
* Verify async operations complete
* Add timeouts to async operations

=== Flaky Tests

*Problem:* Tests pass sometimes, fail sometimes

*Solution:*
* Remove dependencies on timing
* Mock time-dependent operations
* Fix race conditions
* Use deterministic test data

=== Import Errors

*Problem:* Cannot import modules

*Solution:*
[source,bash]
----
# Install in editable mode
pip install -e ".[dev]"

# Verify PYTHONPATH
echo $PYTHONPATH
----

=== Fixture Errors

*Problem:* Fixture not found

*Solution:*
* Check fixture is in conftest.py
* Verify fixture name spelling
* Check fixture scope

== Best Practices

=== General

* Write tests first (TDD when possible)
* Keep tests simple and readable
* One assertion per test (when reasonable)
* Use descriptive test names
* Test edge cases
* Test error conditions
* Keep tests independent
* Avoid test interdependencies

=== Test Organization

* Group related tests in classes
* Use fixtures for common setup
* Keep test files focused
* Mirror source code structure

=### Test Data

* Use realistic test data
* Create reusable fixtures
* Avoid hardcoded values
* Document test data format

=== Coverage

* Aim for high coverage
* Don't chase 100% unnecessarily
* Focus on critical paths
* Test error handling
