== Build System

The project uses standard Python build tools with GitHub Actions CI/CD.

=== Local Build

==== Prerequisites

* Python 3.11+
* pip and virtualenv
* Home Assistant (for validation)

==== Steps

1. Clone repository:
   ```bash
   git clone https://github.com/your-username/ha-owm-precipitation-forecast.git
   cd ha-owm-precipitation-forecast
   ```

2. Create virtual environment:
   ```bash
   python -m venv venv
   source venv/bin/activate  # On Windows: venv\Scripts\activate
   ```

3. Install dependencies:
   ```bash
   pip install -r requirements-dev.txt
   ```

4. Run validation:
   ```bash
   python -m pytest
   black --check custom_components
   isort --check-only custom_components
   flake8 custom_components
   pylint custom_components
   mypy custom_components
   ```

== Continuous Integration

GitHub Actions automatically:
* Validates with hassfest
* Runs test suite
* Checks code quality
* Generates coverage reports

Workflow files: `.github/workflows/`

=== Hassfest Validation

Ensures manifest.json and integration structure are valid:
```bash
python -m script.hassfest
```

=== Test Coverage

Minimum 80% coverage required:
```bash
pytest --cov=custom_components --cov-report=html
```

View coverage: `htmlcov/index.html`

== Release Process

=== Manual Release

1. Update version in:
   * `custom_components/ha_owm_precipitation_forecast/manifest.json`
   * `pyproject.toml`
   * Update `CHANGELOG.md` (if exists)

2. Run tests and linting locally:
   ```bash
   pytest
   black custom_components
   isort custom_components
   flake8 custom_components
   pylint custom_components
   mypy custom_components
   ```

3. Commit changes:
   ```bash
   git add .
   git commit -m "Release v1.0.1"
   ```

4. Create tag:
   ```bash
   git tag v1.0.1
   git push origin --tags
   ```

5. GitHub Actions automatically creates release

=== Automated Release

Release workflow (`.github/workflows/release.yaml`) triggers on tag creation:
* Runs full test suite
* Runs all linting checks
* Creates GitHub release
* Publishes to HACS

== Version Management

Follow Semantic Versioning: MAJOR.MINOR.PATCH

* MAJOR: Breaking changes
* MINOR: New features (backward compatible)
* PATCH: Bug fixes

Example: v1.2.3
